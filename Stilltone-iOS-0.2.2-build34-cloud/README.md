# Stilltone iOS 0.2.2 (34) · 拍摄菜单关闭动画

基于 0.2.2 (33)。目标参考机为 iPhone 14 Pro / iOS 27。实际入口为 StudioApp → SharedCapture。构建和 WebKit 回归结果见 verify/stilltone-build34 分支的 GitHub Actions。真机帧率、拍摄延迟和同场景成像仍待测量。

## 原相机对照进度

Build 30 的色表对中间调采用线性光亮度补偿。FL2 为 −0.35 EV，FL3 和富士 NN 为 −0.40 EV，富士 NC 为 −0.45 EV，富士 CC 为 −0.30 EV。补偿在深阴影和高光中平滑减弱。GR 正片沿用原色表。取景、滤镜成片和相册编辑使用同一组色表。

| 范围 | 当前证据与缺口 |
|---|---|
| UI | 控件依然通过 WKWebView 呈现。已接入 AE/AF 状态和保存成功后的最近照片缩略图；尚无对照录屏验证安全区、横屏、控件位置、命中范围与过渡时间。 |
| 拍照操作 | 代码接入长按测光对焦锁、设备曝光补偿、系统拍摄事件和可用镜头的自动闪光。音量键单拍、手势与系统音量冲突、锁定稳定性需要真机验证。QuickTake、滑动连拍和人像模式尚未实现。 |
| 实况 | 选择滤镜时保留实况意图。静态图和视频帧采用同一 LUT，重新封装原音频（若有）与定时元数据，调用 PhotoKit 校验配对。目前会话未接入麦克风，不能保证实况有声。需要在系统照片中检查长按播放、关键照片时间、色彩边界、方向与重试。 |

## 构建

用 Xcode 16 或更新版本打开 FL-Camera.xcodeproj，选择 FLCamera、开发团队和 iOS 16+ 真机运行。将本目录内容放在测试仓库根目录（包含 .github、Tests 和所有 LUT）后，可手动运行 Build iPhone IPA。工作流先跑回归，再编译并生成 Stilltone-0.2.2-build34-unsigned。该产物需要签名才能安装。

## 拍摄和保存

- 单拍、夜景每一帧与 Live 捕获回调按 AVFoundation uniqueID 匹配，终态到达后结算。相机受中断时暂停快门，进入相册停止取景，仍在采集的请求先完成再停会话。
- 仅照片模式可用；切换模式取消倒计时。变焦过程中允许继续调整倍率，拍摄等待镜头稳定。HEIF 与 JPEG 按实际 codec 能力分别展示。滤镜条可调强度。
- RAW 保留并可切换实时滤镜。原图模式只存 DNG；选择滤镜时，将滤镜 HEIF 和原始 DNG 作为同一照片资产的两个资源写入。渲染失败时提示并保留 DNG。高分辨率优先使用物理主摄的实际支持格式；在 1×、4:3、关闭闪光和夜景的条件下验收 48 MP，检查实际 DNG 像素。相机输出提供 HEIF、RAW；应用内高级修图导出 HEIF。
- 编码后的照片及 Live 配对视频先尝试暂存于 Application Support/PendingCapture，再提交系统相册。保存失败可重试、打开设置、查看相册或经确认后放弃。本地空间不足时可能仅能在内存保留。若异常退出恰好发生在系统写入与本地确认之间，重开后请先核对相册，恢复项不会自动重新提交。配对视频不完整但取得有效静态照片时提示并尝试保留静态照片。
- 成功写入后界面提示“已保存到系统照片”。拍摄前的硬件采集失败以及编码失败会提示错误，此时没有可供重试的已编码成片。

## 相册和编辑

- 系统图库按批读取、监听 PhotoKit 变化，恢复前台及退出高级编辑时刷新。基础编辑返回时处理未保存的改动。
- 高级编辑中“保存草稿”将源文件和配方写入 WKWebView 的 IndexedDB；写入失败留在编辑页。“导出 JPEG”等待系统照片回执，失败可重试，进行中禁止重复提交或退出。草稿属于应用网页存储，清除应用数据也会清除草稿。
- 全尺寸 JPEG 导出分条计算像素，保留相邻行以处理锐化、降噪，并显示进度。完整输出画布、JPEG 编码和跨桥传输仍受机型内存及 WebKit 尺寸限制。

## 本地回归

从源码根目录运行：

```text
node Tests/camera-ui.test.cjs
node Tests/thumbnail-receiver.cjs
node Tests/build17.test.cjs
node Tests/build18.test.cjs
# WebKit 布局回归由 verify-build34 工作流运行，覆盖 393×852、852×393 和抽屉拖动。
python Tests/verify_bundle.py
```

build17 测试运行包内页面代码，模拟设备、IndexedDB、Canvas 和系统保存回执。包括模式切换、变焦快门门控、RAW 往返、滤镜强度、夜景设置、保存反馈、草稿持久化及重复导出。资源测试可附加 ZIP 路径逐文件比对。

| 操作 | 验收依据 |
|---|---|
| 启动、拒绝相机、系统设置授权、锁屏、相机会话中断及回前台 | 取景和快门状态一致，恢复后拍一张，检查系统照片中的新增资产。打开图库后确认停止消耗相机帧。 |
| 3 秒计时中进入图库或后台；快速切前后摄、捏合变焦、变焦停止后拍摄 | 被取消的任务不拍摄；倍率稳定后快门恢复。核对首张实际镜头和构图。 |
| 选择 1:1、滤镜和亮度，进出 RAW；原图和滤镜分别横竖拍摄、边缘点按对焦 | RAW 显示原始画幅，返回 HEIF 后恢复原配方；核对文件类型、像素、方向、自拍镜像和四角。 |

| 主摄和前摄分别在明暗环境试自动及强制夜景 | 对照当前 ISO、曝光时长和采集帧数。观察运动重影、成片亮度及多帧失败时的反馈。 |
| 高级编辑保存草稿后关闭、杀进程再开；连续导出两次；测试图库有限访问和 iCloud 资源 | 草稿可重新编辑；进行中的重复按钮不新增第二张；导出失败能重试，图库成功后刷新。 |
| 12 MP、48 MP 输入在低内存和较新机型导出；小屏、横屏与 VoiceOver 检查交互 | 记录实际导出尺寸、峰值内存、失败恢复及触控命中。确认锐化、裁切、旋转和径向调整在预览与成片一致。 |
